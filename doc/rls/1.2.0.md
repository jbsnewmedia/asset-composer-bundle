## Release 1.2.0 – Changelog Summary

This release adds Symfony 8 support and moves the toolchain to PHP 8.4, alongside security hardening of asset path validation and support for symlinked Composer path repositories. Users benefit from a future-proof framework baseline, safer asset serving, and more flexible local development setups.

* **Symfony 8 Support**
  Composer constraints now allow `symfony/framework-bundle` and `symfony/yaml` `^8.0` (in addition to `^6.4|^7.0`), with codebase and tests aligned accordingly.
  *Benefit: ready for Symfony 8 projects while staying compatible with 6.4 and 7.x.*

* **PHP 8.4 Required**
  The bundle now targets PHP `>=8.4` (previously `>=8.1`); Docker, CI, and QA tooling were aligned to the new baseline.
  *Benefit: modern language features and a consistent, current runtime across local and CI environments.*

* **Stricter Directory Traversal Protection**
  `getAssetFileName()` now rejects any asset path containing `..` up front with a `BadRequestHttpException`, before any file resolution happens.
  *Benefit: traversal attempts are blocked early and deterministically.*

* **Support for Symlinked Composer Path Repositories**
  The project-dir containment check was refactored into a dedicated `assertFileInsideProjectDir()` method, applied consistently after file resolution. Path comparison now normalizes directory separators and trailing slashes, so vendor directories provided via symlinked Composer path repositories resolve correctly.
  *Benefit: local path-repository workflows (e.g., monorepo-style development) work without false security violations.*

* **More Robust Path Handling**
  Hardened validation logic with expanded test coverage for security and edge cases.
  *Benefit: safer asset serving and more predictable behavior across environments.*

* **Documentation Expanded**
  Added detailed instructions for using Composer and local assets in Twig templates to both the English and German README.
  *Benefit: faster onboarding and clearer guidance for local asset workflows.*

**Compatibility:** Breaking Change – Requires PHP ≥8.4 (support for 8.1–8.3 dropped); Symfony 6.4, 7.x, and 8.x are supported.
