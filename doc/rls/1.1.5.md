## Release 1.1.5 – Changelog Summary

This release introduces a configurable switch for generating **relative vs. absolute asset URLs**, plus a round of cleanup and test consistency tweaks. The new default of relative URLs improves flexibility across environments and reverse proxies.

* **Configurable URL Mode**
  Adds `useRelativePath` (default: `true`) to toggle between relative and absolute asset URLs.
  Benefit: Easier deployment behind proxies/CDNs and fewer hard-coded hosts; opt out to keep absolute URLs.

* **Router Generation Honors Setting**
  `AssetComposer` now picks `RELATIVE_PATH` or `ABSOLUTE_URL` based on `useRelativePath`.
  Benefit: Predictable URL generation aligned with your configuration.

* **Service & DI Wiring**
  Injects `$useRelativePath` via `config/services.yaml` and exposes it as container parameter `asset_composer.use_relative_path`.
  Benefit: Straightforward per-env control through Symfony config.

* **Configuration Schema Update**
  Adds `use_relative_path` boolean to the bundle configuration with a default of `true`.
  Benefit: Clear, first-class configuration rather than hardcoded behavior.

* **Test Suite Consistency**
  Normalizes path concatenation (no spaces) and minor test cleanups.
  Benefit: More readable tests and fewer diffs going forward.

* **Rector & Style Polishing**
  Minor coding-style adjustments (path arrays, trailing commas) in `rector.php`.
  Benefit: Cleaner codebase and consistent tooling behavior.

* **License Text Fix**
  Corrects company name capitalization in LICENSE.
  Benefit: Accurate legal attribution.

**Compatibility**: Backward compatible; note the new default generates relative URLs—set `asset_composer.use_relative_path: false` to keep absolute URLs.
